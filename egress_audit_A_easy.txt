==============================================================================
HUK 낚시 대회 앱 — 데이터 사용량 점검 (쉬운 풀이)
범위: 데이터베이스에서 앱으로 흘러오는 데이터 (Database Egress)
==============================================================================

[ 먼저, 'Egress'가 뭔가요? ]

Egress = 서버에서 앱으로 "내려보내는 데이터의 양"입니다.
Supabase는 이 양에 따라 돈을 받습니다. 핸드폰 데이터 요금처럼요.

문제는 두 가지로 발생합니다.
  (a) 앱이 한 번에 너무 많이 받아옴 (필요 없는 것까지)
  (b) 같은 걸 자꾸 또 받아옴 (캐시 안 함)

이번 점검은 (a)를 중심으로, 앱이 데이터베이스에서 데이터를 받아올 때
"필요 이상으로 큰 짐을 들고 오는 곳"을 찾아낸 결과입니다.

==============================================================================
요약: 17곳에서 문제 발견. 그중 4곳이 가장 심각.
==============================================================================

심각도 단계:
  Critical (긴급) ─ 지금도 돈이 줄줄 새고 있음. 사용자 늘면 폭발.
  High (높음)     ─ 사용자/데이터 늘면 빠르게 악화됨.
  Medium (중간)   ─ 개선 여지 있음. 당장 큰 문제는 아님.
  Low (낮음)      ─ 마이너 최적화.

| 분류             | 발견 | 긴급 | 높음 | 중간 | 낮음 |
| 실시간 구독       | 0   | -   | -   | -   | -   |  ← 문제 없음
| 실시간 채널       | 0   | -   | -   | -   | -   |  ← 문제 없음
| 데이터 쿼리       | 17  | 4   | 6   | 6   | 1   |  ← 여기서 다 나옴
| 서버 함수(RPC)    | 0   | -   | -   | -   | -   |  ← "쓰지 않아서" 생긴 문제

==============================================================================
가장 심각한 4곳 (Critical) — 비유로 설명
==============================================================================

────────────────────────────────────────────────────────────────────────────
[1] 피드(메인 게시판) 진입 시 — "도서관에서 책을 다 빌려옴"
────────────────────────────────────────────────────────────────────────────
지금 일어나는 일:
  사용자가 피드 화면에 들어가면, 지금까지 올라온 모든 게시물을 한 번에
  내려받습니다. 게시물이 1만 개면 1만 개를 다 받아옵니다.
  화면에는 위에서부터 20개만 보이는데도요.

비유:
  도서관에 책 1권 보러 갔는데, 사서가 도서관 책 전체를 들고 와서
  "여기서 골라보세요" 하는 상황.

영향:
  지금은 게시물이 적어서 티가 안 나지만, 사용자와 게시물이 늘면
  앱 진입 1번에 수 MB씩 데이터를 씁니다. 이게 Egress 비용으로 직결됩니다.

해결 방향:
  "20개씩 받기 + 스크롤 내릴 때 추가로 20개 받기" 식으로 바꿔야 합니다.
  (인스타그램·트위터가 다 그렇게 합니다)

────────────────────────────────────────────────────────────────────────────
[2] 리그 점수 랭킹 화면 — "1등 한 명 보려고 전 국민 점수표를 받음"
────────────────────────────────────────────────────────────────────────────
지금 일어나는 일:
  랭킹 탭 진입 시, 앱이 모든 사용자의 모든 리그 점수 기록을 다 받아옵니다.
  그리고 핸드폰에서 일일이 더해서 1~10등을 뽑아냅니다.
  화면에 보여주는 건 10명뿐인데도요.

비유:
  반에서 1등 누군지 알려고, 모든 학생의 시험지 원본을 다 가져와
  교실에서 직접 채점하고 합산하는 상황. 학교 교무실에서 점수만
  뽑아 알려주면 끝나는 일인데요.

영향:
  앱을 쓸수록 데이터가 누적되니, 시간이 지날수록 매 진입의 비용이 커집니다.

해결 방향:
  서버(Supabase)에 "Top 10만 계산해서 줘"라고 부탁하는 함수를 만들면,
  앱은 10명분 데이터만 받습니다.

────────────────────────────────────────────────────────────────────────────
[3] 내 프로필 화면 — "내 통계 보려고 같이 참가했던 모든 사람들 자료까지 받음"
────────────────────────────────────────────────────────────────────────────
지금 일어나는 일:
  내 프로필 화면에서 "참가 횟수, 우승 횟수"를 보여주려고,
  내가 참가했던 모든 리그의 모든 참가자, 모든 게시물을 다 받아옵니다.
  내 우승 여부를 핸드폰에서 직접 계산하기 위해서요.

비유:
  "내가 작년에 몇 번 1등 했지?" 가 궁금해서, 내가 참가했던 모든 대회의
  모든 참가자 기록을 인쇄해서 가져와 직접 비교하는 상황.

영향:
  10개 리그에 참가했고 평균 30명, 평균 50개 게시물이면
  → 1만 5천 건의 데이터를 매번 받아옵니다. 프로필 한 번 들어갈 때마다요.

해결 방향:
  서버에 "내 우승 횟수, 참가 횟수만 알려줘" 라고 부탁하는 함수 추가.

────────────────────────────────────────────────────────────────────────────
[4] 마이리그 시즌 통계 — [3]과 똑같은 일을 또 함
────────────────────────────────────────────────────────────────────────────
지금 일어나는 일:
  마이리그 화면에서 시즌 통계를 보여주려고, [3]번과 거의 똑같은 데이터를
  또 받아옵니다. 두 화면이 결과를 공유하지 않아요.

비유:
  같은 자료를 두 번 출력해서 두 부서에 따로 가져다주는 상황.
  사실 한 번만 받으면 됩니다.

해결 방향:
  [3]번 해결책을 만들 때 같이 쓰도록 정리.

==============================================================================
"높음(High)" 6곳 — 짧게
==============================================================================

(5) 개인 기록 랭킹: [2]번과 똑같은 패턴이 한 번 더 있음.

(6) 리그 상세 진입: 데이터베이스에서 "*"(전체 컬럼)을 받아옴.
    필요 없는 큰 컬럼(소개글, 이미지 URL 배열 등)까지 매번 동반.

(7) 리그 참가자 수 표시: "참가자 100명"이라는 숫자만 필요한데,
    100명의 ID를 다 받은 다음 "그 길이가 100"이라고 세고 있음.
    (도서관 책 권수 알려고 책 다 가져오는 격)
    → 이미 같은 코드 안에 "댓글 수 세기"는 올바르게 처리되고 있어서,
      그 방식을 그대로 가져다 쓰면 됨.

(8) 리그 목록: 피드[1]과 동일한 페이지네이션 부재 문제.

(9) 리그 랭킹: [2]번보다 작은 규모지만 같은 구조.
    더구나 화면에서 어떤 행동(참가/취소/승인 등)을 할 때마다 캐시가
    무효화되어 다시 받아옴. 자주 발생.

==============================================================================
중간(Medium) 6곳 — 한 줄씩
==============================================================================

(10) 시즌 점수 합산: 점수 1개만 필요한데 모든 게시물 점수를 다 받아 더함.
(11) 참가자 상세 화면: "*"로 모든 컬럼 받아옴.
(12) 리그 종료 시 보너스 저장: 참가자 수만큼 따로따로 저장 요청 보냄.
(13) 댓글 목록: 댓글 수 제한 없음. 인기 게시물에서 부담.
(14) 심사 탭: 리그 게시물 전체 받아옴.
(15) 인증 대기/이력: 갯수 제한 없음.
(17) 프로필 만들기: 한 화면 들어갈 때 7~8번에 나눠 받음.

==============================================================================
낮음(Low) 1곳
==============================================================================

(16) 최대어 카드(1장): 카드 한 장 보여주는데 비디오 URL 등 불필요한
     컬럼까지 동반.

==============================================================================
잘 되어 있는 부분 (칭찬할 점)
==============================================================================

- 실시간 구독/채널은 DM 외에는 깔끔함. 누수 없음.
- 대부분 쿼리가 "받을 컬럼"을 명시하고 있음 (CLAUDE.md 규칙 준수).
- 일부 화면은 5분/3분 캐시 적용 중.
- 댓글 수는 서버에서 미리 세서 받는 올바른 방식 사용 중.
  → 이 방식을 다른 곳에도 똑같이 적용하면 큰 개선.

==============================================================================
정리: 핵심은 두 가지
==============================================================================

1. "서버가 계산해야 할 일을 핸드폰이 하고 있다"
   → 랭킹/통계는 서버에서 미리 계산해 결과만 받아야 합니다.

2. "필요한 만큼만 받지 않고 다 받는다"
   → 피드/리그 목록은 20개씩 끊어서 받아야 합니다.

이 두 가지만 고쳐도 데이터 사용량(=비용)이 크게 줄어듭니다.
사용자가 늘어나도 비용이 천천히 늘게 됩니다.
